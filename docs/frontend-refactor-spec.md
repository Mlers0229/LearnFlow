## LearnFlow 前端重构需求说明（展示效果 & 页面功能清单）

> 目的：  
> 把现有前端已经实现的功能和后续想要的展示效果，用一份文档说清楚，方便后面按“设计稿”来重构代码、统一 UI 风格，并且便于论文/答辩直接引用。

---

## 1. 重构目标（用人话讲）

- **视觉统一**：所有页面和卡片用同一套配色、间距、圆角、阴影，看起来像一个完整产品，而不是零散的 Demo。
- **信息更清晰**：学习计划、每日任务、资源和练习题的信息结构要清楚，让“老师 / 答辩老师”一眼能看出你系统在做什么。
- **交互更友好**：
  - 有明显的“加载中 / 空数据 / 错误”提示；
  - 点击按钮时有反馈（禁用状态 / loading 文案）；
  - 页面布局在 13~15 寸屏幕上截图效果好，适合论文插图。
- **功能不大改，展示更好看**：本轮重构**不新增复杂业务逻辑**，重点是把已有功能“包装”得更直观、可演示。

---

## 2. 全局设计规范（适用于所有页面）

> 说明：你不希望页面里出现大块“空白区域”，所以整体设计改为**信息偏紧凑、版心更宽**的布局，而不是中间一小张大卡片四周大量留白。

- **布局**
  - 顶部保留统一导航栏：Logo + 菜单 + 当前用户信息（登录状态）。
  - 页面主体区域采用**宽版心 + 分栏布局**：
    - 背景可以仍用浅灰（例如 `#f3f4f6`），但顶部和左右只保留少量边距；
    - 内容区宽度建议占视口宽度的 80%~90%，两侧留白较窄（避免中间一小块内容、四周很空）。
  - 卡片使用方式：
    - 不再只用“一张巨大主卡片包住一切”，而是**多张内容块卡片拼成页面**（例如：左侧列表一张卡 + 右侧详情一张卡）；
    - 适当减小卡片的内边距（padding），让列表、表单和表格更紧凑。
- **配色建议**
  - 主色：蓝紫（例如 `#4f46e5`），用于按钮和高亮。
  - 辅色：绿色（例如 `#22c55e`）用于完成度、成功状态。
  - 文本颜色：标题 `#111827`，正文 `#374151`，辅助文字 `#6b7280`。
- **卡片 & 按钮**
  - 卡片统一圆角（6~8px），浅阴影，卡片之间保持一致但**不过分夸张**的间距；
  - 列表类/表格类区域可以更“后台化”一些，类似管理系统的紧凑风格。
  - 按钮样式统一：主按钮（实心）、次按钮（描边）、文字按钮（链接样式）。
- **状态展示**
  - 统一的三类提示：
    - `loading`：简短文字 + 小 loading 图标或动画；
    - `empty`：友好的引导文案（告诉用户下一步可以做什么），但避免整屏只剩一个空组件，周围保持其他信息块；
    - `error`：红色文字 + 简短错误说明（建议带“请稍后重试”等）。
- **响应式（简单版）**
  - 优先保证在 **笔记本宽度 1280px~1440px** 上展示良好；
  - 移动端可以只保证“不会完全错位”，暂不追求完美适配。

### 2.1 组件库选型：Naive UI 使用约定

> 本次重构统一采用 **Naive UI** 作为组件库，下面约定常用组件的使用方式，便于后续代码风格统一。

- **布局与容器**
  - 页面骨架：`n-layout` + `n-layout-header` + `n-layout-content`；
  - 卡片：统一使用 `n-card`，设置 `bordered`、`hoverable`、`segmented` 等属性增强层次感；
  - 区块间距：优先使用 `n-space` / `n-grid` 控制间距和排列。
- **表单与输入**
  - 统一使用 `n-form` + `n-form-item` 包裹 `n-input` / `n-input-number` / `n-select` / `n-radio-group`；
  - 表单校验使用 `rules` 属性集中管理，避免手写很多 if 判空；
  - 提交时通过 `formRef.validate()` 触发校验，并配合 `n-message` 给出结果提示。
- **按钮与交互反馈**
  - 主操作按钮：`n-button type="primary"`；
  - 次要操作：`n-button` 默认 / `quaternary` 风格；
  - 文本类操作（例如“查看详情”）：可使用 `text` 类型按钮或自定义链接样式；
  - 全局通知：`useMessage()` / `useNotification()`，用于成功/失败反馈。
- **列表与表格**
  - 历史计划、资源管理等偏“数据”的区域，优先用 `n-data-table`；
  - 简单列表可使用 `n-list` + `n-list-item` 或若干 `n-card` 组合。
- **状态与标签**
  - 状态标签：`n-tag`（不同 `type` 映射不同状态，如 `success / warning / error / default`）；
  - 进度条：`n-progress type="line"` 展示计划完成度；
  - 空状态：`n-empty`；
  - 错误提示：`n-alert type="error"` 或 `n-result status="error"`；
  - 加载中：在局部区域使用 `n-spin` 包裹内容。

## 3. 页面功能与展示需求清单

下面按“页面 / 组件”列出你需要保留、以及重构时要重点注意的功能点。

### 3.1 顶层布局：`UserLayout` / `AdminLayout`

- **UserLayout（普通用户端）**
  - 顶部导航：
    - Logo + 系统名称：`LearnFlow 智能学习系统`；
    - 菜单项：
      - “生成学习计划” → `/`
      - “历史计划” → `/history`
      - “关于系统” → `/about`
      - “Agent 调用日志（调试）” → `/debug/agent-logs`（可以放在“更多 / 开发者”下拉中，避免打扰普通用户）
    - 右侧用户区：
      - 未登录：显示“登录 / 注册”按钮；
      - 已登录：显示用户名 + 角色标签（`student / admin`）+ 退出登录。
  - 内容区域：
    - 所有子页面统一放在一张**白色主卡片**中（现在已经有类似结构，重构时注意统一 padding 与阴影）。

- **AdminLayout（管理端）**
  - 顶部导航：
    - 标题：“LearnFlow 管理端”；
    - 菜单：
      - “资源管理” → `/admin/resources`
      - 返回用户端入口（例如“返回学习端”）。
  - 风格与 UserLayout 保持一致，但可以稍微“偏工具化”（表格为主）。

### 3.2 生成学习计划页：`PlanGeneratorPage.vue`

- **表单区域**
  - 字段：
    - 学习目标（多行文本）；
    - 学习周期（周数，数字输入或下拉）；
    - 每天学习时长（小时，数字输入或下拉）；
    - 当前基础水平（单选：零基础 / 有一点基础 / 进阶）。
  - 展示要求：
    - 使用网格或两列布局对齐 label 和输入框；
    - 每个字段下方可显示简单提示（例如“建议 4~12 周”“每天至少 30 分钟”等）。
  - 交互：
    - 点击“生成学习计划”按钮后：
      - 按钮进入 `loading` 状态（文案如“正在生成计划…”），禁止重复点击；
      - 下方显示“提示文字 + loading”而不是空白。
  - Naive UI 建议：
    - 使用 `n-card` 包裹整个表单区域；
    - 表单：`n-form` + `n-form-item` + `n-input` / `n-input-number` / `n-select` / `n-radio-group`；
    - 提交按钮：`n-button type="primary"`，配合 `loading` 属性。

- **结果展示区域**
  - 当有返回计划时：
    - 使用 `PlanResultCard` 展示计划标题、起止日期、每日任务、进度条等；
    - 顶部可显示一行小提示：“以下计划已保存，可在『历史计划』中再次查看和操作。”
  - 当还没有生成计划时：
    - 显示引导文案（例如“一键生成你的专属学习计划，从左侧表单开始填写吧。”）。
  - Naive UI 建议：
    - 使用单独的 `n-card` 展示结果区域，未生成时在卡片中放 `n-empty` + 引导文案；
    - 结果存在时，将 `PlanResultCard` 放入该 `n-card` 内，保证布局统一。

### 3.3 历史学习计划页：`PlanHistoryPage.vue`

- **推荐整体布局风格（参考 `DemoPlanPage.vue`）**
  - 顶部增加一行紧凑的“统计卡片”区域：
    - 卡片 1：计划总天数 + 起止时间；
    - 卡片 2：已完成天数 + 剩余天数；
    - 卡片 3：完成度百分比 + 进度条。
  - 下方采用左右两列结构：
    - **左列：计划列表 + 日程概览**
      - 上半部分：学习计划列表（类似 Demo 中的左上卡片），展示标题、时间范围、状态、水平等；
      - 下半部分：当前计划的“每日任务时间轴”列表（类似 Demo 中的“日程概览”），点击某一天后高亮并在右侧展示详情；
    - **右列：当前选中日的详细信息**
      - 显示当日主题、状态标签、所属计划标题；
      - 列出当日任务列表 + 操作按钮（标记完成、细化任务、查看资源、生成练习题）；
      - 作为 `PlanResultCard` 重构后的核心展示区域。

- **左列：计划列表 + 日程概览（实现要点）**
  - 计划列表展示字段：
    - 标题（没有标题时用“学习计划 #ID”）；
    - 时间范围（startDate ~ endDate）；
    - 状态标签（active / completed / cancelled）；
    - 学习水平（beginner / intermediate / advanced）。
  - 日程概览展示字段：
    - 日期（左侧）；
    - 当日主题 + 状态标签（右侧）。
  - 交互：
    - 计划列表支持 hover 高亮与选中态（背景色 + 边框颜色变化）；
    - 点击计划会刷新下方日程列表，并自动选中该计划的第一天；
    - 点击日程列表中的某一天，在右侧展示该天的详细信息。
  - Naive UI 建议：
    - 整体使用两个 `n-card`（计划列表 + 日程概览），内部用 `n-space` 排列；
    - 每条计划/每天的展示使用简单 `div` + `n-tag` 实现 hover / active 效果；
    - 无计划或无日程时使用简短文字提示，不使用整屏大空态。

- **右列：当前选中日详情（实现要点）**
  - 详情头部：
    - 标题：当日主题；
    - 副标题：所属计划标题；
    - 右侧操作区：状态 `n-tag` + 一组 `n-button`（标记完成 / 细化任务）。
  - 详情主体：
    - 学习任务列表（ul 列表）；
    - 资源与练习相关按钮区域（查看推荐资源 / 生成练习题）。
  - Naive UI 建议：
    - 整体使用一个 `n-card` 承载，未选中任何日程时用 `n-empty` + 提示文案；
    - 头部信息 + 操作放在卡片顶部一行/两列布局，任务和按钮分成两个“子区块”方便排版。

### 3.4 计划详情组件：`PlanResultCard.vue`

这是前端展示的**核心组件**，重构时重点美化。

- **头部信息**
  - 计划标题；
  - 计划 ID（用等宽字体小号显示）；
  - 起止日期；
  - 整体完成度进度条（已实现，重构时注意视觉优化：颜色渐变、数值文本清晰）。

- **整份计划资源推荐区**
  - 一行按钮：“为本计划加载推荐资源”；
  - 下方用**卡片列表**展示每条资源：
    - 标题（可点击打开新标签页）；
    - 标签：适用水平 / 预计时长 / 标签列表；
    - 推荐理由（灰色小字）。
  - 空/错误状态：
    - 空：提示“暂时没有匹配到资源，可以先在『资源管理』中补充资源后重试。”
    - 错误：红色错误信息。
  - Naive UI 建议：
    - 最外层用一个大的 `n-card`，头部使用 `header` 插槽展示标题 + 时间范围；
    - 完成度进度条使用 `n-progress`；
    - 全局资源列表可以用 `n-list` + `n-list-item` 或多张小 `n-card`。

- **每日任务卡片**
  - 布局：
    - 日期 + 当日主题；
    - 状态标签（未开始 / 进行中 / 已完成 / 延迟）；
    - 操作按钮区：`标记为已完成`、`细化今日任务`、`查看当日推荐资源`、`生成 / 查看当日练习题`；
    - 任务列表（小圆点列表）。
  - 行为：
    - “标记为已完成”：更新 day.status，同时局部更新进度条（或在下次刷新时体现）；
    - “细化今日任务”：调用后端细化任务，展示更细的任务列表；
    - “查看当日推荐资源”：按天调用 RAG 推荐，并在日卡片内展示资源列表；
    - “生成 / 查看当日练习题”：
      - 调用后端 `/api/plan/day/{dayId}/exercises`；
      - 展示 1–2 道题目，每题包含：
        - 题干；
        - 本地输入框（用户写答案，暂不入库）；
        - “查看参考答案与讲解”的折叠区域。
  - 状态提示：
    - 各按钮在 `loading` 时要禁用 + 文案变化（例如“正在细化…”、“正在生成练习题…”）；
    - 错误时在对应日卡片中显示红色错误文字。
  - Naive UI 建议：
    - 每天一张 `n-card`，卡片 header 显示日期 + 主题 + 状态 `n-tag`；
    - 操作按钮使用 `n-button` 组合，并配合 `size="small"` 与 `secondary` / `tertiary` 风格；
    - 当日资源和练习题可用 `n-collapse` 或分块标题分隔，错误提示用 `n-alert type="error"`。

    - 列表部分使用 `n-data-table`，各状态列使用 `n-tag` 渲染；

### 3.8 Agent 调用日志调试页：`AgentLogDebugPage.vue`

- 入口路径：`/debug/agent-logs`（可在导航中归类到“关于 / 调试”）。
- 功能：
  - 表单区：
    - 输入框：traceId（可选）；
    - 数量 limit（默认 50，可调）；
    - “刷新日志”按钮。
  - 列表区（表格）：
    - 列：ID、时间、traceId、Agent 名称、耗时(ms)、请求摘要、响应摘要；
    - 文本使用等宽字体，超长内容自动截断。
- 用途：
  - 主要面向**开发者 / 论文演示**，普通用户不用频繁访问；
  - 重构时注意表格清晰、适合截屏。
  - Naive UI 建议：
    - 表单区使用 `n-space` + `n-input` + `n-input-number` + `n-button`；
    - 列表区使用 `n-data-table`，为时间、Agent 名称、耗时等列设置合适的列宽；
    - 当无数据时使用 `n-empty`，错误时使用 `n-alert type="error"`。

## 4. 可选的通用小组件（视时间而定）

- **状态标签组件**：例如 `<StatusBadge type="completed" />`，统一渲染状态颜色与文案。
- **Tag 标签组件**：用于展示资源的标签、等级等小块信息。
- **Loading / Empty / Error 统一组件**：减少各页面重复写样式。
- **通知 / Toast 组件**：用于在保存成功 / 失败时给出轻量提示。

## 5. 前端重构建议顺序

1. **先统一顶层布局和全局样式**（导航栏 + 主卡片 + 背景色），不改动业务逻辑。
