# 数据库恢复 Runbook

负责人：Data；应用连接池处置由 Backend/Agent 协同。Dashboard：Grafana `LearnFlow / Database`。关联告警：`LearnFlowDatabasePoolSaturated`、`LearnFlowAgentDatabasePoolSaturated`、`LearnFlowQueueMetricsStale`。

## 日常可恢复性检查

1. 由托管平台确认自动备份已启用、最近一次成功时间、保留期和 PITR 时间窗口。
2. 备份状态至少每日进入受控监控；失败或最旧可恢复点无法满足 15 分钟 RPO 时告警。
3. 每次 Schema 或重大数据变更后，在隔离实例执行一次恢复抽查，验证 Flyway、关键约束和应用只读冒烟。
4. 不把备份 URI、访问令牌、数据库内容或用户 Payload 写入工单和演练报告。

## 数据事故恢复

1. 宣布数据事故并冻结写入，记录故障时刻和最后已知正常时刻。
2. 保存当前实例、日志和备份元数据，不在原实例上执行未经演练的修复。
3. 优先将 PITR 恢复到隔离实例，校验 Flyway 版本、关键表数量、外键和抽样业务数据。
4. 由应用负责人确认读写冒烟测试后切换连接；旧实例保持只读，直到观察窗口结束。
5. 记录实际 RPO/RTO、丢失范围和需要重放的幂等任务。

## 演练场景

### 误删

仅对 staging 合成数据执行批准的删除。删除后立即冻结写入，选择删除前恢复点并恢复到隔离实例；验证删除前数据存在、删除后边界符合预期、跨用户归属未破坏。

### 数据库不可用

通过托管平台受控故障或 staging 网络策略阻断访问。确认 Backend/Agent readiness 关闭、连接池获取有界且告警触发；切换或恢复后验证连接池、readiness、登录和计划查询。

### 区域故障

验证备用区域具有相同不可变镜像、Secret、对象存储访问和可恢复数据库。区域、流量切换和 DNS 细节必须在平台选定后补入执行记录；未建立备用区域时不得标记通过。

## 恢复证据

记录带时区的事故开始、选定恢复点、隔离实例可用和应用恢复时间。实际 RPO 不得超过 15 分钟，RTO 不得超过 60 分钟。证据至少包含供应商备份元数据、Flyway 校验、关键表/约束、所有权隔离、应用冒烟和清理记录。

禁止事项：未经备份直接删表、手工改写 Flyway 历史、将未校验恢复实例接入生产流量。
