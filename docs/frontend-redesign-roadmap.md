# LearnFlow 前端全页面重做与优化路线图

> 状态：执行中（批次 6 管理端已收口，批次 7 全局质量继续推进）
> 制定日期：2026-08-26
> 适用范围：`frontend/` 全部用户端、管理端页面及前端工程体系
> 执行原则：分批改造、保持后端 API 兼容、每批可验证、可部署、可回滚

## 1. 改造目标

LearnFlow 前端下一阶段主线调整为“全页面重做与体验优化”。本次改造不仅更新视觉样式，还将同时解决信息架构、组件边界、状态管理、请求缓存、表单校验、响应式、可访问性、性能和自动化测试问题。

核心目标：

- 重做现有 15 个页面和 2 套布局。
- 保留已经可用的后端接口和业务能力，不因前端重构造成流程回退。
- 建立统一的 LearnFlow Design System。
- 将超大型单文件组件拆分为可维护的业务模块。
- 完善加载、空数据、失败、重试、权限不足、任务中断等状态。
- 同时支持桌面、平板和手机端。
- 建立单元测试、组件测试、浏览器 E2E 和可访问性检查。
- 每个批次独立提交、部署到 staging、验收并支持镜像回滚。

当前主要问题：

- 多个页面文件超过 1000 行，历史计划页超过 2000 行。
- 页面容器同时承担数据请求、业务状态、交互和大量样式，维护成本较高。
- Naive UI 与自定义元素混用，表单、反馈和按钮交互不完全一致。
- 大量样式分散在全局 CSS 和页面 scoped CSS 中。
- 用户端顶部导航信息密度高，移动端主要依靠自动换行。
- 服务端状态、请求重试和缓存主要由页面分别管理。
- JavaScript 缺少完整的接口与业务模型类型约束。
- 缺少完整组件测试、浏览器 E2E、可访问性和视觉回归门禁。
- 当前缺少统一的 403、404、系统错误和离线状态页面。
- Agent 调试路由只要求登录，应调整为管理员权限。

## 3. 技术栈决策

### 3.1 保留项

以下核心技术继续使用：

- Vue 3.5
- Vite 8
- Vue Router
- Naive UI
- Nginx 容器化部署

不计划迁移到 React、Next.js 或其他大型 UI 框架。当前 Vue 业务代码和后端联调成果可以继续复用，整体换框架的成本和风险高于收益。

### 3.2 新增与调整项

| 领域 | 当前方案 | 目标方案 |
| --- | --- | --- |
| 开发语言 | JavaScript | 渐进迁移 TypeScript |
| 客户端状态 | 手写 reactive store | Pinia |
| 服务端状态 | 页面手动请求 | TanStack Vue Query |
| 表单与校验 | 页面分别实现 | VeeValidate + Zod |
| API 类型 | 手写 API 模块 | 优先通过 OpenAPI 生成类型客户端 |
| UI 体系 | Naive UI + 分散 CSS | Naive UI 基础组件 + LearnFlow Design System |
| 图标 | 无统一体系 | Lucide Vue |
| 管理图表 | 手工数据块 | ECharts 按需、延迟加载 |
| 单元与组件测试 | Vitest | Vitest + Vue Test Utils + MSW |
| 浏览器测试 | 不完整 | Playwright |
| 可访问性 | 无自动门禁 | axe-core + 人工键盘检查 |
| 组件工作台 | 无 | Histoire 或 Storybook，实施前二选一 |

### 3.3 技术约束

- TypeScript 采用渐进迁移，不要求一次性改写所有文件。
- 不同时维护两套 UI 组件库。
- Naive UI 改为按需加载，避免全量注册。
- API 路径、鉴权方式和后端数据契约默认保持兼容。
- 如果后端 OpenAPI 描述不完整，先修正契约再生成客户端。
- ECharts、Markdown 编辑器等较重模块必须路由级或组件级懒加载。
- 新增依赖必须说明解决的问题、包体影响和替代方案。

## 4. 设计系统与信息架构

### 4.1 视觉方向

整体视觉定位为“专注、安静、清晰的智能学习工作台”。

- 保留青绿色品牌主色，重新定义完整色阶。
- 暖色只用于重点提示、进度和风险，不作为大面积背景。
- 用户端采用明亮、低干扰的学习空间。
- 管理端使用更高信息密度的独立控制台主题。
- 减少装饰性文字、重复标签和无业务意义的状态描述。
- 动效保持克制，并尊重 `prefers-reduced-motion`。

### 4.2 Design Token

统一建立：

- 品牌色、功能色、中性色和状态色。
- 字号、字重、行高和内容最大宽度。
- 4/8 像素间距体系。
- 圆角、边框、阴影和层级。
- 动效时长与缓动曲线。
- 桌面、平板、手机断点。
- Naive UI 主题变量映射。

### 4.3 导航结构

用户端桌面布局调整为“侧边主导航 + 简洁顶部状态栏”：

- 学习计划
- 执行与复盘
- 练习
- AI 对话

次级入口：

- 上传学习资源
- 个人设置
- 关于 LearnFlow

管理端使用独立侧边导航：

- 总览
- 资源管理
- 模型配置
- Agent 日志
- 用户管理

移动端使用抽屉或底部主导航，不再依赖顶部导航换行。

## 6. 前端目录与组件重构

目标目录：

```text
src/
  app/
  layouts/
  features/
    auth/
    plans/
    exercises/
    chat/
    resources/
    profile/
    admin/
  shared/
    api/
    components/
    composables/
    design-system/
    stores/
    types/
    utils/
```

组件约束：

- 页面文件只负责路由级组合。
- 页面容器目标控制在 300 行以内。
- 单个业务组件原则上不超过 500 行。
- 请求、权限、状态映射和错误处理不得在多个页面重复实现。
- 表格、筛选器、状态徽标、任务进度、确认弹窗统一封装。
- 所有异步页面都必须提供加载、空数据、失败、重试和权限不足状态。
- 所有危险操作使用统一确认组件，禁止直接调用 `window.confirm`。

## 9. 性能与可访问性指标

Staging 目标：

- LCP 不高于 2.5 秒。
- CLS 不高于 0.1。
- INP 不高于 200 毫秒。
- 所有路由使用代码分包。
- ECharts 等重组件延迟加载。
- 360px 宽度无横向滚动和操作遮挡。
- 核心页面达到 WCAG 2.2 AA。
- 所有交互可使用键盘完成。
- 动画遵守 `prefers-reduced-motion`。
- 页面不得泄露 API Key、Token 或敏感日志内容。

## 10. 发布与回滚策略

- 每个批次独立提交，不采用一次性整体替换。
- 每批必须依次通过 lint、类型检查、单元测试、组件测试和构建。
- 核心批次必须通过 Playwright E2E。
- 每批先部署 staging，并保留上一镜像 digest。
- 出现核心流程回归、错误率明显升高或安全问题时立即回滚。
- 前端重构默认不修改后端 API；需要修改时必须先完成契约兼容方案。
- 批次 3、批次 4 和批次 6 完成后设置独立人工验收门禁。
