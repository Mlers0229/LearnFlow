# ADR-0013：版本化学习事件与可解释掌握度画像

- 状态：Accepted
- 日期：2026-08-23
- 关联：M4-LEARN-01、Sprint 17

## 背景

LearnFlow 已经保存学习日状态、练习记录和资源反馈，但这些数据分散在不同业务表中，无法回答“某次掌握度变化由哪些行为造成”，也无法在算法升级后稳定重算。现有 `skill_focus` 和学习日标题仍是自由文本，样本量不足时不能使用高复杂度模型制造虚假的确定性。

## 决策

1. Spring Backend 是学习事件与掌握度的唯一写入方；Agent 不获得相关表权限。
2. 新增追加式 `learning_event`，只记录事件类型、可信用户、知识点、来源引用、数值信号、算法所需权重和不含正文的证据摘要。
3. 题干、参考答案、用户答案、AI 反馈、资源评论、Prompt、Token 和身份原文不得复制到学习事件、日志或遥测。
4. 知识点第一版使用确定性规范化：压缩空白、转小写后计算 SHA-256 稳定键；展示名保留受限长度文本。未提供 `skill_focus` 时退回学习日标题，仍为空时使用“未分类”。
5. Mastery v1 使用可解释加权平均，不使用 BKT/DKT：
   - 练习得分：`score / 100`，权重 `1.0`；只有正确性时使用 `1/0`，权重 `0.75`。
   - 学习日完成：信号 `0.75`，权重 `0.35`。
   - 学习日延期：信号 `0.25`，权重 `0.20`。
   - 开始学习：信号 `0.55`，权重 `0.10`。
   - 重置、复习标记和资源反馈仅保留轨迹，权重为 `0`，避免把点击或满意度误当成知识掌握。
6. 得分为 `sum(signal * weight) / sum(weight)`；置信度为 `min(0.95, 1 - exp(-effectiveWeight / 4))`。低样本天然得到低置信度，API 必须同时返回样本量和有效权重。
7. 写入事件后在同一事务内重算受影响的用户－知识点画像。事件键唯一，重复提交不重复计分。
8. 删除练习时追加 `EXERCISE_DELETED` 反向事件并重放画像；不删除或改写原事件。
9. `algorithm_version` 是画像唯一键的一部分。算法升级使用新版本重放，不覆盖旧版本结果。

## 事务与权限

- 学习日状态、练习保存/删除、资源反馈与事件写入处于同一数据库事务。
- 所有用户 API 仅从 JWT 安全上下文取得用户 ID，不接受客户端身份字段。
- Backend 对新表具有业务所需权限；Agent 显式无权访问。
- V16 为纯扩展迁移。回滚时先关闭 `LEARNFLOW_MASTERY_ENABLED` 并停止读写新 API；表保留用于审计和前向修复。

## 可观测性

- 指标只使用固定事件类型、结果和算法版本标签。
- Span 不记录知识点名称、用户 ID、来源 ID或异常消息。
- 事件写入失败必须使对应业务事务失败，禁止返回虚假的成功结果。

## 后续

- M4-LEARN-02 才允许掌握度影响计划、资源和练习排序。
- 只有真实样本量、校准结果和对照评估满足门禁后，才评估 BKT；当前不引入 DKT。
