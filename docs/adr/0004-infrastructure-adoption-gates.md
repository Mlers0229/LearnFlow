# ADR-0004：基础设施引入门槛

- 状态：Accepted
- 日期：2026-08-21
- 决策人：LearnFlow 维护者

## 背景

生产路线图包含异步任务、缓存、限流和高可用能力，但过早引入 Redis、消息队列或 Kubernetes 会增加单人项目的运维成本。

## 决策

- 消息队列：当任务超过同步请求预算、需要持久重试/取消，或批量 Embedding/索引无法在单进程可靠完成时引入。选型前先定义任务状态、幂等键、重试和死信语义。
- Redis：仅在需要跨副本限流、短期共享状态或经指标证明的热点缓存时引入。认证长期状态和任务事实状态不放在仅内存型 Redis 中。
- Kubernetes：初期托管容器平台无法满足副本、灰度、Secret、网络策略或成本要求时再评估；不因技术栈完整性而引入。
- 新 Agent/框架：只有现有确定性服务无法表达动态语义决策，并且评测集证明收益时才引入。

## 取舍

延迟引入减少故障面和交付时间，但部分能力会先使用 PostgreSQL 或平台原生组件实现。

## 风险

如果流量增长快于预期，基础设施准备时间可能不足。M2 容量告警必须在达到预计上限 60% 时触发评估。

## 回滚

新增组件必须通过适配器接入，并保留数据库/同步降级路径；取消组件时不得改变业务 API 契约。
